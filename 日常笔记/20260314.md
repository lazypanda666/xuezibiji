# 端口

## 1. 什么是网络端口？

在网络技术中，端口包括**逻辑端口**和**物理端口**两种类型。

- **物理端口**是用于**连接物理设备**之间的接口，如ADSL Modem、集线器、交换机、路由器上用于连接其他网络设备的接口。
- **逻辑端口**是指逻辑意义上**用于区分服务**的端口，比如用于浏览网页服务的80端口，用于FTP服务的21端口等。
  我们这里讲的是逻辑端口。

---

## 2. 端口的作用

**端口号**的主要作用是表示一台计算机中的特定进程所提供的服务。

网络中的计算机是通过**IP地址**来代表其身份的，它只能表示某台特定的计算机，

但是一台计算机上可以同时**提供很多个服务**，如数据库服务、FTP服务、Web服务等，

我们就通过端口号来区别相同计算机所提供的这些不同的服务，如常见的端口号21表示的是FTP服务，端口号23表示的是Telnet服务，端口号25指的是SMTP服务等。

---

## 3. 端口的分类

TCP与UDP段结构中端口地址都是16比特，可以有在0---65535范围内的端口号。

按照**端口号**分类：

- **公认端口**：0~1023。它们紧密绑定于一些服务，通常这些端口的通讯明确表明了某种服务的协议，如：80端口对应与HTTP通信，21端口绑定与FTP服务，25端口绑定于SMTP服务，135端口绑定与RPC（远程过程调用）服务。
- **注册端口**：1024~49151。它们松散的绑定于一些服务，也就是说有许多服务绑定于这些端口，这些端口同样用于其他许多目的，如：许多系统处理端口从1024开始
- **动态或私有端口**：49152~65535。理论上，不应为服务分配这些端口，通常机器从1024开始分配动态端口。例外：SUN的RPC端口从32768开始。

按照**协议类型**分类：按协议类型划分可分为TCP端口、UDP端口、IP端口、ICMP。

- **TCP端口**：即传输控制协议端口，需要在客户端和服务器之间建立连接，这样可以提供可靠的数据传输。常见的包括FTP的21端口，Telnet的23端口，SMTP的25端口，HTTP的80端口。
- **UDP端口**：即用户数据报协议端口，无需在客户端和服务器端建立连接，安全性得不到保障。常见的DNS的53端口，SNMP（简单网络管理协议）的161端口，QQ使用的8000和4000端口。
- **保留端口**：UNIX有保留端口号的概念，只有超级用户特权的进程才允许给它自己分配一个保留端口号。这些端口号介于1~1023之间，一些应用程序将它作为客户与服务器认证的一部分。

端口使用的**注意事项**

- 不要使用端口号**小于1024**的端口。
- 端口号一般习惯为**4位整数**，在同一台计算机上端口号**不能重复**，否则，会产生端口号冲突。 
- **客户端**端口号因存在时间很短暂又称**临时端口号**，大多数TCP/IP实现给临时端口号分配1024---5000之间的端口号。大于5000的端口号是为其他服务器预留的 。

# IP地址

## 1. 概述

### 什么是 IP 地址

IP地址（Internet Protocol Address）是**互联网协议地址**，用于唯一标识网络中的一台设备。每个连接到网络的设备都需要一个IP地址才能进行通信。

- 计算机网络中的 **“电话号码”**
- 设备在互联网中的 **唯一标识符**

互联网通信流程：

```
设备A → 通过IP地址找到 → 设备B
```

因此 IP 地址的核心作用是：

1. **标识设备**
2. **定位设备**
3. **实现网络通信**

------

## 2. IP地址的基本特性

### 唯一性

在同一网络中：

- 每台设备必须拥有 **唯一 IP 地址**

否则会产生：  `IP冲突`

表现为：

- 网络无法通信
- 局域网连接异常

------

### 层次性

IP地址通常由两部分组成：

```
IP地址 = 网络号 + 主机号
```

例如：

```
192.168.1.10
```

含义：

| 部分      | 含义 |
| --------- | ---- |
| 192.168.1 | 网络 |
| 10        | 主机 |

层次结构的**作用**：

- 提高路由效率
- 方便网络管理

------

### 全局性

IP地址在互联网中具有**全球唯一性**。

地址分配由**国际机构统一管理**，例如：

- IANA（Internet Assigned Numbers Authority）
- 各区域互联网注册机构（RIR）

例如：

| 机构  | 地区 |
| ----- | ---- |
| APNIC | 亚太 |
| ARIN  | 北美 |
| RIPE  | 欧洲 |

------

## 3. IPv4 地址

### IPv4地址结构

IPv4 是目前最广泛使用的 IP 地址版本。

特点：

- **32位地址**
- 分为 **4个字节**

表示方法：

```
a.b.c.d
```

示例：

```
192.168.1.1
```

每个字段范围：

```
0 — 255
```

例如：

```
11000000.10101000.00000001.00000001
```

转换为十进制：

```
192.168.1.1
```

IPv4 总地址数量：

```
2^32 ≈ 43亿
```

------

### IPv4地址分类

| 类型 | 地址范围                    | 用途     |
| ---- | --------------------------- | -------- |
| A类  | 1.0.0.0 — 126.0.0.0         | 大型网络 |
| B类  | 128.0.0.0 — 191.255.0.0     | 中型网络 |
| C类  | 192.0.0.0 — 223.255.255.0   | 小型网络 |
| D类  | 224.0.0.0 — 239.255.255.255 | 组播     |
| E类  | 240.0.0.0 — 255.255.255.255 | 实验     |

A/B/C 类用于普通通信。 

------

### 私有IP地址

为了缓解 IPv4 地址不足，定义了**私有IP地址**。

私有地址范围：

| 范围                          | 类型 |
| ----------------------------- | ---- |
| 10.0.0.0 – 10.255.255.255     | A类  |
| 172.16.0.0 – 172.31.255.255   | B类  |
| 192.168.0.0 – 192.168.255.255 | C类  |

特点：

- 只在**局域网**使用
- **不能直接**访问互联网

访问互联网需要：

```
NAT (Network Address Translation)
```

------

## 4. IPv6 地址

### IPv6出现的原因

IPv4 最大问题：  `地址耗尽`

IPv4地址：  `2^32 ≈ 43亿`

随着互联网发展：

- 手机
- 服务器
- IoT设备

数量爆炸式增长。

因此出现： `IPv6`

------

### IPv6地址结构

IPv6 地址：   `128 位`

地址数量：

```
2^128  ≈ 340万亿亿亿亿
```

理论上：

> 地球每平方米可以分配数千个IP地址。

------

### IPv6表示方式

格式：

```
X:X:X:X:X:X:X:X
```

示例：

```
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

简写：

```
2001:db8:85a3::8a2e:370:7334
```

------

### IPv6地址类型

#### 单播地址

发送到：

```
一个设备
```

------

#### 组播地址

发送到：

```
一组设备
```

类似：

```
广播升级版
```

------

#### 任播地址

发送到：

```
最近的设备
```

用于：

- CDN
- DNS

------

## 5. IP地址在网络中的作用

IP协议是互联网**协议栈核心**。

**协议栈**：

```
应用层
传输层 (TCP/UDP)
网络层 (IP)
数据链路层
物理层
```

IP 位于：  `网络层`

作用：

1. **地址标识**
2. **数据路由**
3. **网络互联**

IP负责：  `数据包路由`

而：`TCP`    负责：  `可靠传输`

------

### 公网IP

- 可以直接访问互联网

例如：

```
8.8.8.8
```

### 私网IP

特点：

- 不能直接访问互联网

例如：

```

```

## 7. 动态IP 与 静态IP

### 动态IP

由：   `DHCP`   自动分配。

特点：

- 会变化
- 家庭宽带常见

------

### 静态IP

特点：

- 固定不变
- 服务器常用

用途：

- 网站服务器
- 数据中心
- 远程访问

------

## 8. IP地址发展趋势

互联网发展趋势：

```
IPv4 + IPv6 共存
```

过渡技术：

1. **双栈**

```
IPv6逐渐取代IPv4
```

# 协议

## 1. 基本概念

### 什么是协议

在计算机网络中，**协议（Protocol）**是指在网络通信过程中，通信双方必须遵循的一组规则和约定。

协议主要规定三个方面：

| 要素 | 含义         |
| ---- | ------------ |
| 语法 | 数据的格式   |
| 语义 | 各字段的含义 |
| 时序 | 通信顺序     |

例如：

```
客户端 → 请求
服务器 → 响应
```

这些规则确保不同设备能够正确通信。 

简单理解：

> 协议 = 网络通信规则

类似：

```
人类语言 = 交流规则
网络协议 = 计算机交流规则
```

------

## 2. 为什么需要网络协议

计算机网络由不同厂商设备组成，如果没有统一规则，**设备之间无法通信**

网络协议解决的问题：

1. 数据如何**表示**
2. 数据如何**发送**
3. 数据如何**接收**
4. **出现错误**如何处理

计算机网络本质上的组成：

```
硬件 + 软件 + 协议（计算机网络的核心）
```

------

## 3. 网络协议的分层思想

为了降低复杂度，网络采用 **分层设计**。

最典型模型：

### OSI七层模型

```
应用层
表示层
会话层
传输层
网络层
数据链路层
物理层
```

------

### TCP/IP 五层模型

现实互联网采用：

```
应用层
传输层
网络层
数据链路层
物理层
```

这种分层思想可以：

```
降低系统复杂度
提高模块化
方便协议设计
```

------

## 4. TCP/IP协议族

互联网最重要的一组协议：   `TCP/IP 协议族`

Internet 使用该协议进行通信。 

协议族结构：

```
应用层协议
   ↓
传输层协议
   ↓
网络层协议
   ↓
数据链路层协议
```

------

## 5. 常见网络协议

### 应用层协议

应用层**直接为用户提供服务**

常见协议：

| 协议  | 功能     |
| ----- | -------- |
| HTTP  | 网页传输 |
| HTTPS | 加密网页 |
| FTP   | 文件传输 |
| SMTP  | 邮件发送 |
| DNS   | 域名解析 |

例如：

```
浏览器访问网页
```

流程：

```
HTTP请求 → Web服务器 → 返回网页
```

------

### 传输层协议

传输层负责：    **端到端通信**

常见协议：

#### TCP

特点：

```
面向连接
可靠传输
有序传输
```

TCP保证：

```
无丢失
无重复
按序到达
```

因此适合：

```
网页
文件传输
邮件
```

#### UDP

特点：

```
无连接
不可靠
速度快
```

适合：

```
视频
语音
直播
```

TCP 和 UDP 的核心区别：

| TCP      | UDP    |
| -------- | ------ |
| 可靠     | 不可靠 |
| 面向连接 | 无连接 |
| 速度慢   | 速度快 |

传输层通过 **端口号** 识别不同应用进程。 

#### TCP为什么可靠？

- ACK确认机制
- 重传机制
- 序列号（保证顺序）
- 流量控制
- 拥塞控制

------

## 6. 网络层协议

```

```


## 9. 协议封装

网络通信中数据会**逐层封装**。

发送数据：

```
应用层数据
   ↓
TCP头 + 数据
   ↓
IP头 + TCP段
   ↓
帧头 + 数据
```

最终变成：   `比特流`   发送到网络。

接收过程相反：   `解封装`

# 数据包与网络通信

------

## 1. 数据包的本质

### 什么是数据包？

数据包（Packet）是网络中**传输数据**的**基本单位**

本质：

- 数据不会“裸传”
- 必须**结构化封装**

------

### 为什么需要数据包？

如果不打包：

- 数据会**无序**
- 无法识别**来源/目标**
- 无法进行**校验**
- 无法进行**重传控制**

本质问题：   **无法管理通信**

### 数据包 vs 帧

| 名称   | 层         | 特点 |
| ------ | ---------- | ---- |
| 数据包 | 网络层     | IP   |
| 帧     | 数据链路层 | MAC  |

------

## 2. 分层模型

### TCP/IP分层

| 层级       | 作用         | 数据名称      |
| ---------- | ------------ | ------------- |
| 应用层     | 用户数据     | Data（数据）  |
| 传输层     | 端口、可靠性 | Segment（段） |
| 网络层     | IP寻址       | Packet（包）  |
| 数据链路层 | MAC寻址      | Frame（帧）   |

------

### 分层的意义

> **高内聚，低耦合**

优点：

- **降低复杂度**
- **模块解耦**
- **易维护**
- **可扩展**

------

## 3. 数据封装与解封装

### 封装过程

```
应用层数据
↓
TCP头 + 数据
↓
IP头 + TCP数据
↓
MAC头 + IP数据
↓
比特流（0101）
```

每一层都在“加头”

------

### 解封装

```
帧 → 包 → 段 → 数据
```

 一层一层拆

------

## 4. IP vs MAC

### 本质区别

| 类型    | 作用           |
| ------- | -------------- |
| IP地址  | **跨网络**定位 |
| MAC地址 | **局域网**定位 |

> **IP决定去哪，MAC决定交给谁**

------

### 为什么不能用MAC跨网络？

- MAC是**平面地址（无层级）**，无法进行路径规划
- IP是**分层地址**，适合路由

------

### 为什么需要IP和MAC？

- IP用于**跨网络定位**
- MAC用于**局域网传输**

---

### 第一跳看IP还是MAC？

- 看MAC（目标是网关）

------

### 为什么IP不变但MAC变化？

- IP是**端到端**地址
- MAC是**逐跳**地址

### 网关（路由器）坏了会怎样？

| 项目       | 是否可用     |
| ---------- | ------------ |
| DNS        | 可能（缓存） |
| 外网通信   | ❌ 不可       |
| 局域网通信 | ✅ 可         |

------

### 同一局域网通信是否需要路由器？

- ❌ 不需要
- ✔ 直接通过ARP获取目标MAC通信

## 5. 数据传输核心机制

### 逐跳传输规则

> **IP不变，MAC每一跳都会变**

------

### 示例

```
电脑 → 路由器A → 路由器B → 服务器
```

| 跳数       | 目标MAC |
| ---------- | ------- |
| 电脑 → A   | 路由器A |
| A → B      | 路由器B |
| B → 服务器 | 服务器  |

> **IP是端到端的，MAC是逐跳的**

------

## 6. 同网段 vs 跨网段

### 判断逻辑

| 情况     | 行为       |
| -------- | ---------- |
| 同网段   | 直接发送   |
| 不同网段 | 发送给网关 |

------

### MAC选择

| 情况     | 目标MAC  |
| -------- | -------- |
| 同网段   | 目标主机 |
| 不同网段 | 网关     |

> **同网段直连，跨网段走网关**

------

## 7. ARP协议

### 作用

> **IP → MAC**

------

### 工作流程

当ARP缓存不存在：

1️⃣ 广播请求：

```
谁是这个IP？
```

2️⃣ 目标回应：

```
我是，我的MAC是xx
```

3️⃣ 写入缓存

------

### 关键点

- ARP只在**局域网**使用
- **不跨网络**

------

### DNS vs ARP

| 协议 | 作用          |
| ---- | ------------- |
| DNS  | **域名 → IP** |
| ARP  | **IP → MAC**  |

------

## 8. 完整通信流程

> 从输入网址到数据发送：

1️⃣ DNS解析 → 获取IP
2️⃣ 判断是否同网段
3️⃣ ARP解析 → 获取MAC

# 广义线性模型

为便于观察，我们把**线性回归模型**简写为
$$
y=w^Tx+b
$$
假设我们认为示例所对应的输出标记是在指数尺度上变化，那就可将输出标记的对数作为线性模型逼近的目标，即

$$
lny=w^Tx+b
$$
这就是“**对数线性回归**” ，它实际上是在试图让$e^{w^Tx+b}$逼近 y。上式在形式上仍是线性回归，但实质上已是在求取输入空间到输出空间的**非线性函数映射**，如图所示。这里的对数函数起到了将线性回归模型的预测值与真实标记联系起来的作用。

![image-20260321003936770](C:\Users\wangyongshuai\AppData\Roaming\Typora\typora-user-images\image-20260321003936770.png)

更一般地，考虑单调可微函数 g(⋅)，令
$$
y=g^{−1}(w^Tx+b)
$$
这样得到的模型称为“**广义线性模型**” ，其中函数 **g(⋅)**称为“**联系函数**” 。

显然，对数线性回归是广义线性模型在 **g(⋅)=ln(⋅)时的特例**。

广义线性模型的参数估计常通过**加权最小二乘法**或**极大似然法**进行。

# Lasso回归、Ridge回归和弹性网络回归

## 1. 从最小二乘出发（统一起点）

### 标准线性回归（矩阵形式）

$$
y= X\beta + \varepsilon
$$

最小二乘：
$$
\min_\beta \|y - X\beta\|_2^2
$$
展开：
$$
\|y - X\beta\|^2 = (y - X\beta)^T (y - X\beta)
$$

------

### 解的不稳定性（本质问题）

当：

- $X^T X$**不可逆**（共线性）
- 或**接近奇异**

则：

$(X^T X)^{-1} \text{不稳定}$

**小扰动 → 大变化（高方差）**

------

## 2. Ridge 回归（L2）

------

### 优化问题

$$
\min_\beta \|y - X\beta\|^2 + \lambda \|\beta\|_2^2
$$

即：
$$
\lambda \sum \beta_j^2
$$

------

### 拉格朗日等价形式

约束形式：
$$
\min \|y - X\beta\|^2 \quad s.t. \quad \|\beta\|_2^2 \le t
$$
**与惩罚形式等价**

------

### 梯度推导

目标函数：
$$
J(\beta) = (y - X\beta)^T(y - X\beta) + \lambda \beta^T \beta
$$
展开：
$$
= y^T y - 2y^T X\beta + \beta^T X^T X \beta + \lambda \beta^T \beta
$$
求导：
$$
\nabla J = -2X^T y + 2X^T X \beta + 2\lambda \beta
$$
令为0：
$$
X^T X \beta + \lambda \beta = X^T
$$

------

### 核心结论：

$$
\hat{\beta} = (X^T X + \lambda I)^{-1} X^T y
$$

------

### 特征值角度理解

设：
$$
X^T X = Q \Lambda Q^T
$$
则：
$$
(X^T X + \lambda I)^{-1} = Q(\Lambda + \lambda I)^{-1}Q^T
$$
本质：

- 小特征值 → 被“抬高”
- 避免除以接近0

**稳定性提升的根本原因**

------

### 偏差-方差推导

**Ridge**：

- 增加偏差
- 降低方差

**用偏差换稳定性**

------

### 概率解释（贝叶斯）

假设：
$$
\beta \sim \mathcal{N}(0, \sigma^2 I)
$$
则：
$$
\max P(\beta|y) \Rightarrow \text{Ridge}
$$
**Ridge = MAP估计（高斯先验）**

------

## 3. Lasso 回归（L1）

------

### 优化问题

$$
\min_\beta \|y - X\beta\|^2 + \lambda \|\beta\|_1
$$

### 为什么困难？

- $|\beta| $  在 0 不可导

- 必须用：**次梯度**

------

### 次梯度定义

$$
\partial |\beta| = \begin{cases} 1 & \beta > 0 \\ [-1,1] & \beta = 0 \\ -1 & \beta < 0 \end{cases}
$$

------

### 一维问题完整推导

考虑：
$$
\min_\beta \frac{1}{2}(y - x\beta)^2 + \lambda |\beta|
$$
设：
$$
z = x^T y, \quad a = x^T x
$$
问题变为：
$$
\min \frac{1}{2}a\beta^2 - z\beta + \lambda |\beta|
$$

### 分情况讨论：

------

#### 情况1：β>0\beta > 0β>0

$$
a\beta - z + \lambda = 0 \Rightarrow \beta = \frac{z - \lambda}{a}
$$

------

#### 情况2：β<0\beta < 0β<0

$$
a\beta - z - \lambda = 0 \Rightarrow \beta = \frac{z + \lambda}{a}
$$

------

#### 情况3：$\beta = 0$

成立条件：
$$
|z| \le \lambda
$$

------

### 最终解（软阈值）：

$$
\beta = \text{sign}(z)\cdot \max(|z| - \lambda, 0)
$$

------

### 几何本质（必须理解）

- L1约束 = 菱形
- 解点常落在“角上”

⇒ 某些 $\beta = 0$

------

### 为什么能做特征选择？

因为：
$$
|z| \le \lambda \Rightarrow \beta = 0
$$
小特征直接被“截断”

------

### 概率解释

Lasso = MAP：
$$
\beta \sim Laplace(0, b)
$$
拉普拉斯分布更“尖锐” → 稀疏 

------

## 4. Elastic Net

------

### 优化问题

$$
\min_\beta \|y - X\beta\|^2 + \lambda_1 \|\beta\|_1 + \lambda_2 \|\beta\|_2^2
$$

### 本质来源

为了解决 Lasso 的两个问题：

- 只能选 ≤ n 个变量 
- 强相关变量只选一个 

------

### 推导理解

Elastic Net =
$$
\text{Lasso} + \text{Ridge}
$$
即：

- **L1：稀疏**
- **L2：稳定**

------

### 强凸性

加入 L2 后：

目标函数变为**强凸**

⇒ 解唯一 

------

### 几何解释

| 方法        | 几何       |
| ----------- | ---------- |
| Ridge       | 圆         |
| Lasso       | 菱形       |
| Elastic Net | “圆角菱形” |

既能压缩又能选变量

------

### 分组效应（重点）

强相关变量会一起被选中 

------

## 5. 三者统一推导框架

------

### 正则化统一形式

$$
\min_\beta \|y - X\beta\|^2 + \lambda \Omega(\beta)
$$

------

### 三者终极对比

| 维度   | Ridge    | Lasso    | Elastic Net |
| ------ | -------- | -------- | ----------- |
| 正则   | L2(平滑) | L1(稀疏) | L1+L2(混合) |
| 稀疏性 | ❌        | ✅        | ✅           |
| 稳定性 | ✅        | ❌        | ✅           |
| 共线性 | 强       | 弱       | 强          |
| 解     | 闭式     | 数值     | 数值        |
